# 技术与能力进化

- **推理栈成为模型竞争的一部分**：DeepSeek 把生产服务框架与 token 编解码组件开放出来；Google 则宣布 vLLM、SGLang 可通过 TorchTPU 原生 PyTorch 后端使用 TPU。Google 提到 KV 缓存（复用已计算的注意力键和值）、推测解码、长上下文、预填充与解码分离，以及低精度量化等支持，并引用 SemiAnalysis InferenceX 与合作方部署数据。相关性能结论适用于公告引用的模型、硬件与测试设置。([Google 开发者公告](https://developers.googleblog.com/en/announcing-new-vllm-and-sglang-inference-engines-on-tpu/))

- **Kimi 的提升来自后训练与长程强化学习工程**：Kimi 说明 K3.1 Pro 是在 K3 上增加后训练算力，并优化强化学习框架、长上下文推理、沙盒和轨迹调度。厂商用 167 个任务和 420 次独立审查作示例，称模型修正了人体步态模拟器中的 36 处肩部肌肉力臂错误，使模拟从数秒内跌倒改善到连续行走 11.2 秒。这是公司展示的内部任务；它能说明长程调试案例，不能替代独立复现。([Kimi 技术博客](https://www.kimi.ai/blog/kimi-k3-1-pro))

- **模型分数要和成本、速度、任务边界一起看**：Kimi 在 Artificial Analysis 综合指数为 55，但该榜每项任务成本约 2.11 美元；MiniMax 为 42，约 0.22 美元/任务。它们并非同一能力等级的简单排序：Artificial Analysis 指数覆盖 10 项任务，Kimi 的价格、输出 token 与单任务时长也不同。MiniMax 的 170 token/s 是厂商报告的中位输出速度，不是 AA 的同一测试指标。([Artificial Analysis Kimi 指数与任务成本](https://artificialanalysis.ai/models/comparisons/kimi-k3-1-pro-vs-gpt-6-1-sol)，[AI Atlas 对 M3.1 Flash 的评测汇总](https://atlas.prashish.com/weeks/2026-10-19))

- **语音代理是系统能力，不只是更自然的 TTS**：Mistral 的 Voxtral 3 把多语种识别、轮次判断、推理、工具调用和语音合成串入实时 SDK；Claude Duet 则把代理放入隔离环境并设置付款、删除等确认点。两者分别展示语音接口与个人工作流代理的系统设计重点。

- **统一管理混合模型的缓存与状态**：SGLang 提出 Unified Memory 层，把注意力模型的 KV cache 与循环模型状态纳入统一内存管理。项目团队在 RTX 5090、Qwen3.5-4B 的缓存压力测试中报告，可保留的前缀数从 10 个增至 19 个；重复查询完成时间从 4.105 秒降至 2.548 秒。这是项目方给出的特定实验结果，显示服务系统需要同时管理不同类型的模型状态。([SGLang 技术说明](https://www.sglang.io/blog/unified-memory))

- **交互式多模态服务从“轮次”走向全双工**：SGLang 的 Omni Interactive Runtime 旨在统一承载原生全双工模型（允许输入与输出同时进行）、轮次式模型和级联模型，让语音或多模态交互不用为每种模型重建服务基础设施。其设计也留下一个开放问题：交互能力应由模型学习多少、由运行时编排多少。([SGLang 说明](https://www.sglang.io/blog/omni-interactive-runtime))

- **编排器变薄，专业智能体变专**：Meta 的经验是把流程控制、重试与一致性检查放在确定性组件中，避免让一个大模型同时承担调度和领域推理。这类分工把可靠性问题从“再加提示词”转到更容易观察和测试的系统设计上；是否适合某个产品，仍要看任务的容错和验证机制。

- **开放模型与工厂化交付并行**：NVIDIA 在同一场 GTC Berlin 既发布模型组合，也提出预制化 AI 工厂。行业竞赛因此不只看模型分数，还看企业能否获得算力、把模型部署在本地，并承担持续推理成本。其部署时限和效率数字仍是 NVIDIA 的目标或估算。
